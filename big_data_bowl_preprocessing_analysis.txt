   • Location: Cell c349c16c, final line: df_final = df_final.fillna(0)


2. OUTLIER DETECTION AND REMOVAL
--------------------------------------------------------------------------------
IQR-Based Outlier Removal:
• Method: Removed plays outside 1.5 × IQR range
• Calculation:
  - Q1 = 25th percentile of playResult
  - Q3 = 75th percentile of playResult
  - IQR = Q3 - Q1
  - lower_bound = Q1 - 1.5 × IQR
  - upper_bound = Q3 + 1.5 × IQR
• Location: Cell a3975417

Results:
• Original dataset: 8,522 plays
• After removal: 8,149 plays
• Removed: 373 outliers (4.4% of data)
• IQR bounds: [-16.50, 27.50] yards

Impact on Model Performance:
• R² improvement: 0.330 → 0.450 (36% relative improvement)
• Rationale: Extreme gains/losses (rare big plays) distorted linear fit
• Trade-off: Better generalization to typical plays at expense of extreme cases

4. FEATURE ENGINEERING
--------------------------------------------------------------------------------

A. TEMPORAL TRANSFORMATION:

   GameClock Conversion:
   • Original: "MM:SS" timestamp format
   • Transformed: Total seconds remaining in quarter
   • Formula: minutes × 60 + seconds

B. PERSONNEL PARSING (Regex-Based):

   Offense Personnel Counts:
   • Extracted from 'personnelO' string (e.g., "1 RB, 3 WR, 1 TE")
   • Positions extracted: RB, TE, WR, OL, QB, LB
   • Method: regex pattern r'(?P<num>\d+)\s+(?P<pos>[A-Z]+)'
   • Output: Columns named <position>_offensecount
   • Missing positions filled with 0

   Defense Personnel Counts:
   • Extracted from 'personnelD' string
   • Positions extracted: DB, DL, LB
   • Output: Columns named <position>_defensecount

C. OFFENSIVE LINE AGGREGATION:

   Per-Play Aggregation from pffScoutingData:
   • Grouped by [gameId, playId]
   • Aggregated statistics (all summed):
     - pff_hit: QB hits allowed
     - pff_hurry: QB hurries allowed
     - pff_sack: Sacks allowed
     - pff_beatenByDefender: Blockers beaten
     - pff_hitAllowed, pff_hurryAllowed, pff_sackAllowed
     - pff_backFieldBlock: Backfield blocks
   • Dropped individual player-level columns:
     - pff_positionLinedUp
     - pff_nflIdBlockedPlayer
     - pff_blockType

D. DERIVED FEATURES (Polynomial & Interaction Terms):

   Polynomial Features (Degree 2):
   • Applied to: yardsToGo, yardlineNumber, down, pff_playAction, pff_hit
   • Method: sklearn.preprocessing.PolynomialFeatures(degree=2)
   • Generated features include:
     - Squared terms (e.g., down², yardlineNumber²)
     - Interaction terms (e.g., yardsToGo × yardlineNumber)
   • Location: Cell 405cea25

   Key Interaction Terms:
   • yardsToGo × yardlineNumber: Distance-to-go × field position
   • down × pff_playAction: Down × play-action usage
   • yardsToGo × pff_playAction: Distance × play-action
   • down × pff_hit: Down × QB pressure

E. CATEGORICAL FEATURES:

   One-Hot Encoded Variables:
   • quarter: Quarter of game (1-4)
   • down: Down (1-4, after filtering out down=0)
   • possessionTeam: Team with possession
   • defensiveTeam: Defending team
   • passResult: C (Complete), I (Incomplete), S (Sack), IN (Interception),
     R (Scramble)
   • offenseFormation: Offensive formation type
   • dropBackType: QB dropback type
   • pff_passCoverage: Pass coverage scheme
   • pff_passCoverageType: Coverage type category

F. CONTINUOUS FEATURES RETAINED AS-IS:

   Game Context:
   • yardsToGo: Distance needed for first down
   • yardlineNumber: Yard line position
   • absoluteYardlineNumber: Absolute field position (0-100)
   • preSnapHomeScore: Home team score before snap
   • preSnapVisitorScore: Visiting team score before snap
   • gameClock: Seconds remaining in quarter (converted)

   Pressure Metrics:
   • defendersInBox: Number of defenders in the box
   • pff_playAction: Play-action indicator (binary)


5. SCALING AND NORMALIZATION
--------------------------------------------------------------------------------
Standard Scaling Applied to Polynomial Features:
• Method: sklearn.preprocessing.StandardScaler()
• Applied BEFORE polynomial transformation
• Prevents numerical issues with squared/interaction terms
• Location: Cell 405cea25
• Pipeline: StandardScaler() → PolynomialFeatures() → LinearRegression()

No Scaling for One-Hot Encoded Features:
• Binary categorical features left unscaled (0/1)

Rationale:
• Polynomial features require scaling to prevent:
  - Numerical instability
  - Disproportionate coefficient magnitudes
  - Multicollinearity issues with squared terms


6. ENCODING
--------------------------------------------------------------------------------
One-Hot Encoding:
• Method: pd.get_dummies() with drop_first=True
• Applied to 9 categorical variables (see section 4E)
• Drop first category to avoid dummy variable trap
• Output dtype: int (0/1)

Binary Target:
• playResult: Continuous yards gained (target variable)
• No encoding required (already numeric)

9. KEY FINDINGS AND ISSUES IDENTIFIED
--------------------------------------------------------------------------------

Strengths:
✓ Comprehensive feature engineering from multiple data sources
✓ Robust handling of missing personnel strings (regex extraction)
✓ Systematic outlier removal improved model fit significantly
✓ Polynomial/interaction terms capture non-linear relationships
✓ Proper scaling before polynomial transformation
✓ VIF analysis identifies multicollinearity issues
✓ Drop-first encoding prevents dummy variable trap

Model Performance Insights:
✓ Linear model R² = 0.330 (33% variance explained)
✓ After outlier removal: R² = 0.450 (45% variance explained)
✓ Polynomial features: Minimal improvement (ΔR² < 0.01)
✓ Feature reduction (df_slimmer): R² = 0.330 (same as full model)

Statistical Findings:
✓ Strongest predictors: passResult dummies (I, IN, R, S)
✓ Significant positives: pff_playAction (+1.9 yds), yardsToGo, down
✓ Non-significant: gameClock, preSnapScores, absoluteYardlineNumber
✓ Durbin-Watson ≈ 2.0 → No autocorrelation
✓ Condition Number = 8,620 (full model) → Multicollinearity present

Potential Issues:
⚠ Target distribution heavily skewed (Jarque-Bera ≫ 0, p < 0.001)
  - Violates OLS normality assumption
  - Mass concentrated near 0 yards with long tails
⚠ Polynomial features provide negligible improvement despite added complexity
⚠ High multicollinearity in full model (VIF > 10 for 4 features)
⚠ VIF reduction sacrifices predictive power (R² drops by 16 points)
⚠ One-hot encoding applied before train/test split (potential data leakage)
⚠ No cross-validation during preprocessing
⚠ Team one-hot encoding creates high dimensionality (32 teams × 2 = 64 columns)
⚠ Class imbalance not addressed for passResult categories
⚠ RMSE ≈ 8.64 yards → Large prediction errors remain

Feature Interpretation Challenges:
⚠ pff_hit has positive coefficient (+0.66 yds) - counterintuitive
  - May indicate confounding (hits occur on longer developing plays)
⚠ Interaction term down × pff_playAction is negative
  - Play-action less effective on later downs
⚠ Squared binary features (e.g., pff_playAction²) equal original feature
  - No true non-linearity captured

================================================================================
MODELING INSIGHTS (FROM EXPLORATORY ANALYSIS)
================================================================================

Linear Regression Results (df_slimmer, with outliers):
• R² = 0.330, Adj. R² = 0.329
• F-statistic = 523.0, p < 0.001 (model is significant)
• Significant features (p < 0.05):
  - yardsToGo (+0.085 yds), down (+0.591 yds), pff_playAction (+1.92 yds)
  - pff_hit (+0.66 yds, counterintuitive)
  - passResult_I (-10.87 yds), passResult_IN (-11.96 yds)
  - passResult_R (-4.69 yds), passResult_S (-18.37 yds)

Linear Regression Results (with outlier removal):
• R² = 0.450, Adj. R² = 0.448 (36% improvement)
• RMSE = √74.7 ≈ 8.64 yards
• Same significant features as above
• Better fit to typical plays, worse on extremes

Polynomial Regression Results:
• R² = 0.4529 (vs. 0.4529 linear) → No improvement
• Top interaction effects:
  - yardsToGo × yardlineNumber (-0.380): Worse when far + long distance
  - yardlineNumber² (-0.284): Diminishing returns near goal line
  - down × pff_playAction (-0.231): Play-action less effective on later downs

VIF Analysis Results:
• High VIF (>10): quarter, defendersInBox, passResult_S, pff_sack
• After removing high-VIF features:
  - R² drops to 0.169 (48% decrease)
  - All remaining VIF < 7
  - Trade-off not worthwhile for this dataset

Key Takeaway:
• Linear model with outlier removal and domain-selected features performs best
• Polynomial features add complexity without predictive gain
• High VIF features contribute significantly despite collinearity
• Target skewness remains a fundamental challenge for OLS regression
